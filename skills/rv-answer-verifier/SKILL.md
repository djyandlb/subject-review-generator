# 答案审查（rv-answer-verifier）

> **本工位优先级最高**：目标是答案 100% 正确。**核心是「对比」不是「上网」**——每道题的答案都必须经过「AI 自审 vs 证据源」的双源对比后才可判定通过，**零漏网、零错位**。错误答案当场改正，绝不放行。
>
> **双源证据定义（重要）**：
> - **证据源 A · 资料原文（永远可用）**：data.json 对应概念的 content / 资料原始文本——本项目的答案天然以资料为准，原文是最好的证据
> - **证据源 B · 外部检索（联网可用时）**：`WebSearch` / `WebFetch` 检索题干关键词取高相关来源
> - 联网**不是必须**，但**对比是必须**——没有对比就判定「通过」= 违规；联网不可达时用「资料原文 + AI 独立复核」作对比依据，且报告如实标注证据来源，不得谎称已联网

## 触发条件

- 独立调用：`/rv-answer-verifier` + data.json 路径
- 由主编排调度（subject-review-generator 第 6 步，出题之后、质检之前）

## 输入

- `data.json` 的 `questions[]`（全部题目）

## 输出（遵循工作目录契约）

- `xxx/data/processed/data.json`（答案修正后的最终版）
- `xxx/<学科名>/answer-audit.md`：修正报告（**落在 `<学科名>/` 子目录，与 `data/` 平级，不在 data 下**），逐题列出（题号 / 类型 / 题干简 / 原答案 / 新答案 / 证据来源 / 修正原因 / 状态；**`题干简` = 题干去空白后的前 20 字缩略**）

## 工作流程（每道题都执行，不漏一题，每步必做 + 验收）

> **流程铁律（防 AI 跳过）**：N 题清单 → N 条审查记录，**0 漏网**；每步过「验收」。
>
> **阶段自检（绝对铁律，防带错交付）**：每步「验收」是执行时核对点（**不逐行自检烧 token**）；**流程末尾做一次阶段自检**——按文末「阶段自检」小节核验产物（能跑脚本的跑脚本看退出码，不能的人工抽查）；**自检全部 PASS 才交付 rv-verifier 阶段①**；任一项 FAIL → 返回返工，禁止带错交付。

### 第 0 步 · 建题清单（🔴 必做，对账基准）
- **动作**：列出 data.json 全部 `questions[]`
- **产物**：必查清单（N 题）
- **验收**：清单 = 全部题目；报告末尾对账
- **依赖**：主编排第 5 步（出题后）

### 第 1 步 · AI 自审（🔴 必做，不看现成答案）
- **动作**：基于题干与自身知识，独立判定答案应是什么
- **产物**：「自审答案」
- **依赖**：第 0 步

### 第 2 步 · 证据对比（🔴 必做，核心步骤）
- **动作**：自审答案 vs 证据源对比
- **命令**：证据源 A 资料原文**必查** + 证据源 B（联网可用时 WebSearch/WebFetch 追加）
- **验收**：每道题至少与一个证据源对比后才可判「通过」；冲突以证据为准当场改正
- **依赖**：第 1 步
- **铁律**：**联网非必须、对比是必须**；联网不可达用「资料原文+AI 独立复核」并**如实标注来源**（不得假装联网）

### 第 3 步 · 答案-题干匹配校验（🔴 必做，防错位）
- **动作**：核对 answer 内容是否对应该题干
- **验收**：无错位（答案对不上 = 重写）；发现一条错位 → **全批次查系统性偏移**
- **依赖**：第 2 步
- **铁律**：**禁止「答案非空即通过」**——非空 ≠ 正确 ≠ 匹配

### 第 4 步 · 按题型核验（🔴 必做）
- **动作**：按题型核验——`single/multi`：answer 在 options 索引范围内且指向内容与题干匹配；`fill`：answer 为填空原词、可在对应概念 content 检索到；`terminology`：answer 为定义要点、对应概念 content 可支撑；`essay`：answer 为要点文本、与题干设问对应；`tf`：answer ∈ {对, 错} 且有事实依据
- **验收**：每题通过对应题型核验项（索引合法 / 原文可检索 / 取值合法）
- **依赖**：第 2 步

### 第 5 步 · 题型复核（🔴 必做，防渲染事故）
- **动作**：主观题（题干含「试述/简述/谈谈/分析/解释…」）**禁止 `type=single/multi`**，一律以 `essay` 类型存储（answer=要点文本，独立题型映射 essay 渲染）；名词解释以 `terminology` 存储（answer=定义要点）
- **验收**：**全部**主观题逐一复核 type=essay / 名解题 type=terminology 且答案完整（不抽样），统计记入报告
- **依赖**：第 4 步

### 第 6 步 · 写报告（🔴 必做）
- **产物**：`<学科名>/answer-audit.md`（逐题：题号/类型/题干简/原答案/新答案/**证据来源**/修正原因/状态）
- **验收**：末尾汇总统计（总题数/外部检索数/资料原文数/AI复核数/修正数/通过数）——用数字自证「对比」覆盖全量
- **依赖**：第 0-5 步
- **铁律**：N 题 → N 条记录 **0 漏网**；证据来源如实标注

## 阶段自检（流程末尾必做，PASS 才交付质检）

- **对账**：N 题清单 → N 条审查记录（0 漏网）
- **报告统计**：answer-audit.md 末尾汇总（总题/外部检索/资料原文/AI复核/修正/通过）数字自证
- **抽查**：修正题复核答案与资料一致、无错位
- **FAIL → 返回补审，禁止带病交付质检**

## 质量要求

- **零漏网**：N 题清单 → N 条记录，0 条漏网（报告末尾对账）
- **必须有对比**：每道题至少与一个证据源（资料原文必查）对比后才可判定「通过」；**禁止无对比直接通过**
- **匹配是底线**：答案必须对应该题干——错位 = 未通过 = 必须重写
- **如实标注证据来源**：联网不可达时用「资料原文 + AI 复核」，报告写清楚，不谎称联网
- **冲突以证据为准**：不得因 AI 自信而放行错误答案；检索结果矛盾 → 追加检索取多来源一致结论
- 修正后答案准确率 100%（复核抽查修正项）

## 协作

- 证据源 B 用 `WebSearch` / `WebFetch` 工具；批量检索可调 `research` skill
- 表述复核可调 `需求转译`
- 产出后交给 `rv-verifier`（阶段①数据校验）质检
