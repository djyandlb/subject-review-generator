# 护栏清单（GUARDRAILS）

> **执行任何 skill 流程前，快速过一遍本清单**。这些是从历史错误中提炼的「必守规则」——只要守住它们，就不会犯那些重复的错误。**很短，务必每次看**。
>
> 与 `EVOLUTION.md`（历史档案，追溯用）不同：本文件是**当前生效的行为约束**，精简到极致。

## 必守规则（13 条）

1. **总体模板 `samples/` 永不改且必须是空壳**——默认骨架 **`基础模板-复习页-v3.html`（v3 Soft UI）**：`KNOWLEDGE_CATEGORIES=[]`、`QUESTION_BANK` 六键皆 `[]`、无学科正文、无 `btnEnhance`（速览由 patch-enhance 注入）。侧栏须 `minmax(0,1fr)` + `.app-sidebar{overflow-y:auto}`。增强只在学科副本做。契约见 `samples/TEMPLATE-v3.md`

2. **复杂 JS/正则用 Write 写文件执行**，不经 bash heredoc（反斜杠 `\s` 会被吞、中文参数会乱、`\f` 被拒）

3. **patch 脚本改完后必须验证**：`node --check` + `vm.Script` 验证目标文件语法，别信「应用成功」的日志

4. **Windows CRLF 陷阱**：副本/模板是 `\r\n`，所有字符串匹配用**正则容忍 `\r?\n`**，不用精确 `\n` 字符串

5. **内容结构化是「重组」不是「精简」**——详情页 content 分点分层、术语加粗，**不删任何考点**（教辅准确性第一）

6. **概念分级只用掌握/熟悉/了解三档，不新立标签**——禁止「必背/高频」等第四种分级标签；isKey 仅作**内部出题覆盖字段**（保证必背考点有题），不是分级、界面不得显示第四种标签；必背/必考考点统一裁为「掌握」。mastery 从资料裁定，禁止按比例硬凑

7. **增强标记【对比表】【树】【流程】【速记】原文必须剥离**（`stripEnhanceMarkers`），否则详情页显示两遍

8. **主题覆盖 `:root` 必须保留模板全部变量**（漏 `--transition-*` 会动画静默失效；v3 另须保留 `--elev-*` / `--space-*` / `--ease*`，否则 Soft UI 与列表过渡塌掉）

9. **速览模式（enhance）侧边栏保持知识点导航**——`renderSidebar` 三态判断，否则点侧边栏跳习题页

10. **章节排序在数据层完成（解析阶段）**——`categories[]` 顺序 = 资料章节实际顺序，前端直接按数组渲染**不二次排序**；遇到分组重复编号（1,2,4,1,2,3,4,5,7）必须拉通为连续「第一章…第九章」；资料无章节名则自动从第一章编号。固化：`rv-data-builder/scripts/renumber-chapters.js`。**禁止前端猜测排序**（如 sortCategoriesByOrder 已被移除）

10b. **习题去重**——资料里重复出现的题必须合并成一道（精确/近似重复都查），不放两份。固化：`rv-data-builder/scripts/dedup-questions.js`，解析与出题后都跑

10c. **知识点去重 = AI 人工判断，不用脚本**——资料里同一知识点反复出现必须合并成一张卡，但必须由 AI 通读资料判断「真正同一知识点」才合并（脚本相似度会误伤：如「抗原」vs「抗体」内容相关但完全不同，绝不能合并）。**宁多勿误合**

11. **新增组件/标题样式必须融入现有主题**——走 CSS 变量、淡色底+主色字、克制不突兀；禁止「直愣愣摆上去」（如渐变胶囊/大块阴影）。模仿现有 `.sidebar-heading` 的克制感

12. **概念卡数量从资料裁定，不设上下限**——教材有多少考点提多少卡，禁止在代理 prompt/流程里写「每章 N 张」「宁缺毋滥」之类的数量限制（会硬砍厚教材考点）；也禁止为凑数注水。数量是资料考点密度的自然结果。固化：rv-data-builder 步骤 3

13. **长文本主动分段注入（防截断/失败，章节级分批）**——任何长文本创建（概念 content 重构、data.json、题库生成）**主动分批生成、分批写回**，禁止「一次整段注入失败后再分段补救」：分批大小**按章节自然划分**——content-refiner **每章概念一批**（约 20-40 卡）写 `data/temporary/refine-part-N.json` 后 `--import` 合并；quiz-designer **每章题目一批**（完成即写回 data.json）。**章节级分批最稳**：分太碎浪费时间/多次调用，分太大一次超上下文截断

14. **AI 生成 JSON 必须校验转义**——AI 建模产出的 data.json 中，content/summary/title 字段的 HTML 富文本可能包含未转义双引号（如 "skip" 病变），**写入后必须用 JSON.parse 验证**，不通过则用脚本修复（参考 `_fix-json*.py` 方案），禁止带语法错误的 JSON 进入后续流程。

15. **subcategory 字段必须是 ID 而非名称**——concept.subcategory 引用的是 subcategories[] 中某项的 id（如 "sub-1-1"），不是 name（如 "适应"）。AI 建模时容易写名称，**check-categories.js 会校验引用完整性**，FAIL 必须修正。

16. **CSS 变量覆盖必须全覆盖**——theme.css 的 `:root` 必须包含模板使用的**全部** CSS 变量（不只是模板 :root 中定义的那些），模板 CSS 中可能引用更多变量（如 `--color-primary`/`--font-body`/`--text-main` 等）。**覆盖前先用 grep 提取模板所有 `var(--xxx)` 引用，确保一一对应**，否则 render-compare.js 会报 CSS 变量缺失。

17. **填空题解析必须识别 `（ ）` 空白标记**——习题文件中填空题常用 `（ ）` 或 `（答案）` 格式，解析器必须识别并提取答案，不能漏解析（会导致填空题题型入口消失）。
