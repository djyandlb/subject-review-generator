# 出题（rv-quiz-designer）

## 触发条件

- 独立调用：`/rv-quiz-designer` + data.json 路径
- 由主编排调度（subject-review-generator 第 5 步）

## 输入

- `data.json`（含 categories 与各概念的 isKey 必背标记）

## 输出（遵循工作目录契约）

- 更新 `xxx/data/processed/data.json`（追加/补全 `questions[]`，覆盖必背概念）
- 每道题满足题库字段规格（id/chapter/type/stem/options/answer/explanation）

## 工作流程（isKey 全覆盖出题，每步必做 + 验收）

> **流程铁律（防 AI 跳过）**：以 `isKey: true` 必背概念为核心，**每个必背概念至少一题**；每步过「验收」。
>
> **阶段自检（绝对铁律，防带错交付）**：每步「验收」是执行时核对点（**不逐行自检烧 token**）；**流程末尾做一次阶段自检**——按文末「阶段自检」小节核验产物（能跑脚本的跑脚本看退出码，不能的人工抽查）；**自检全部 PASS 才交付 rv-answer-verifier**；任一项 FAIL → 返回返工，禁止带错交付。

### 第 1 步 · 建必背清单（🔴 必做）
- **动作**：遍历 data.json 所有 `isKey: true` 概念，建立必背清单
- **产物**：必背清单（isKey 概念 + 章节）
- **验收**：清单覆盖全部 isKey 概念（与 data.json 对账）
- **依赖**：主编排第 4 步（rv-content-refiner 完成、content 已重构）

### 第 2 步 · 逐概念覆盖出题（🔴 必做）
- **动作**：为每个必背概念生成**至少一道题**
- **命令**：题型按概念性质多样化——能出选择出选择、能出判断出判断、名词性出名解（fill）、流程性出填空/简答（fill）；**禁止偷懒成单一题型**（如全部判断题）
- **产物**：data.json `questions[]` 追加
- **验收**：每个 isKey 概念 ≥ 1 题（AC10）；题库多题型混合（在资料可支撑前提下尽量覆盖 single/tf/fill）
- **依赖**：第 1 步清单
- **分段注入（防截断，章节级分批）**：**按章分批出题**（每章题目一批，完成即写回 data.json）；禁止一次生成全部题目（长文本超限被截断），也勿碎片化到单题
- **铁律**：isKey 全覆盖，优先客观题；难出客观题的转简答（**`essay` 类型**，answer 为要点文本）或名词解释（**`terminology` 类型**，answer 为定义）——独立题型独立渲染，勿塞进 fill

### 第 3 步 · 题型生成规则（🔴 必做）
- **动作**：按规则生成各题型（**六类独立**：single/multi/tf/fill/terminology/essay，各有独立入口，勿混类）
- **命令**：选择 `single`（正确项取该概念，**干扰项从同章其它概念 title/summary 提炼**，不重复不歧义）/ 多选 `multi`（正确项为索引数组）/ 判断 `tf`（从 content 改写，**错误陈述只改一处事实**）/ **填空 `fill`（挖 summary/content 关键词挖空，answer 填原词；**空占位统一「____」4 个半角下划线**，禁 3/5/6 个或空格；**多空答案须用分号「；」或顿号「、」间隔**，禁直接连一块）** / **名词解释 `terminology`（见第 4 步，独立题型）** / **简答 `essay`（试述/简述/谈谈类，answer 结构化分点 ①…②… / 1.…2.…，禁一大段无结构）**
- **options 必须纯文本**：每项**禁带「A. 」等序号前缀**——模板自动拼 A./B./C.，数据带前缀会变「A. A. xxx」双序号。正例 `["左心衰竭时肺泡腔内","右心衰竭时肺泡腔内"]`，反例 `["A. 左心衰竭时肺泡腔内"]`
- **验收**：题干源自资料不编造；干扰项不与正确项歧义；**题型分类正确（填空≠名词解释≠简答）**；**options 纯文本无序号前缀**
- **依赖**：第 2 步

### 第 4 步 · 名词解释专项（🔴 必做，先查用户清单）
- **动作**：先查用户资料有无「名词解释」清单；**有则只用清单，无才 AI 生成**
- **命令**：扫描资料原文关键词（名词解释/名词/术语/简答/问答题/考点）；无清单时由 AI 挑 `isKey:true` 名词性概念生成（题面=title，**answer 格式固定为「答案：一句话解释\n答题要点：abc；def」**——第一行「答案：」后用完整一句话解释定义，换行后「答题要点：」列出要点；**禁止**只有 abc 要点无「答案：」解释句、也禁止无「答题要点：」），**`type=terminology` 存储**
- **产物**：名词解释题（type=terminology）
- **验收**：有清单 → 逐条识别（有答案直接采用、无答案从资料补、缺的标待补）；无清单 → isKey 名词性概念全覆盖（宁缺毋滥不注水）
- **依赖**：第 2 步
- **铁律**：**有用户清单时绝不自行生成**（老师固定考点，多余生成画蛇添足）

### 第 5 步 · 题型取舍 + 挂章节 + 去重 + 解析（🔴 必做）
- **动作**：0 题题型自动隐藏；每题挂章节；重复题合并；每题带实质解析
- **命令**：`node <同级skill:rv-data-builder>/scripts/dedup-questions.js <data.json>` 去重 + **`node <同级skill:rv-data-builder>/scripts/check-explanation.js <data.json>` 解析质量机器校验**（路径解析见主编排「路径解析约定」）
- **产物**：data.json `questions[]` 定稿（带 chapter + explanation）
- **验收**：无 0 题题型入口占位；每题 `chapter` 引用存在；无实质重复题；**check-explanation 退出码 0（每题解析为实质解析，非空转）**
- **依赖**：第 2-4 步
- **铁律**：基础题型基线（选择/判断/名词解释）必备（除非资料实在无法支撑）；**解析禁空转——纯答案字母（「A」「ABD」「答案：B」）、纯对错词（「正确」「错误」）、≤4 字过短都是空转，必须补写「为什么对/错、涉及哪个考点」的实质解析**（AI 生成时偷懒只写答案 = check-explanation 会 FAIL 打回）

## 接口契约

- 追加到 `data.json.questions[]`，字段严格按规格：
  - `single`/`multi`：`answer` 为正确选项索引或索引数组，`options` 非空
  - `fill`：`options` 为空数组，`answer` 为填空原词文本
  - `tf`：`options` 为空数组，`answer` ∈ {对, 错}
  - `terminology`：`options` 为空数组，`stem` 为术语名，`answer` 为定义要点文本
  - `essay`：`options` 为空数组，`answer` 为简答要点文本
- 每道题必须带 `explanation`（解析，源自资料内容）

## 阶段自检（流程末尾必做，PASS 才交付答案审查）

- **解析质量**：`node <同级skill:rv-data-builder>/scripts/check-explanation.js <data.json>` 退出码 0（每题实质解析，无空转）
- **必背覆盖**：每个 isKey 概念 ≥ 1 题（对照必背清单逐条核验）
- **题型**：六类独立、无 0 题入口、explanation 非空转
- **FAIL → 返回补写，禁止带病交付答案审查**

## 质量要求

- **必背覆盖率达到 100%**：对照必背清单逐个核验，每个 isKey 概念都有对应题
- 题目内容全部源自资料，**禁止生造事实**
- 干扰项不得含明显错误或与正确项重复
- **解析生成规范（硬性）**：每道题的 `explanation` 必须是 **AI 编写的实质性解析**——说明「为什么选这个答案 / 为什么对/错 / 涉及的核心考点」，禁止「答案：X」「正确」「错误」式的空转。**合格正例**：「A。大叶性肺炎致病菌为肺炎链球菌（革兰阳性双球菌），与题干吻合；B/C/D 非其典型致病菌」。**禁止通用套话/推诿**（「本题考查相关病理学概念…」「……见资料参考答案」「答案依据见资料」这类雷同或让用户自己找答案 = 空转，check-explanation FAIL——解析必须贴本题实际内容）
  - 自选题（single/tf/fill）→ 生成时同步写解析（依据资料 content）
  - **资料原题若无解析或只有「答案：X」** → 也须由 AI 补写解析（源自资料内容，不编造）
  - 判断题解析要写明正确/错误的依据（如「化生发生于同源性细胞之间」）
  - 生成后抽查：解析为空或仅「答案」二字的题必须重写
- **出题后去重**：同一概念多道题若题干实质重复（只改数字/语序/标点），只留一道；多个概念生成出相同题干也合并。可跑 `<同级skill:rv-data-builder>/scripts/dedup-questions.js <data.json>` 复核

## 协作

- 不熟悉领域可调 `research` skill 辅助理解资料
- 产出后必须交给 `rv-answer-verifier` 联网审查答案
- 可调 `需求转译` 复核出题规则
